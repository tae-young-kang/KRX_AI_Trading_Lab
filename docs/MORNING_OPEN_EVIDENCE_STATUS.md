# 가상 시초 근거 상태 조회 — 첫 체결 인증과 구별

## 사용 목적

가상 추천 → 가상 진입의 연결 상태를 확인하되, **거래소의 실제 첫 체결 인증,
키움 모의계좌 주문 체결, 실계좌 주문 체결**과 혼동하지 않기 위한 읽기 전용 점검입니다.

개인 인증을 통과한 텔레그램 채팅에서 다음처럼 조회합니다.

```text
/가상시초근거 2026-10-20
/가상시초근거 2026-10-20 2
```

- 해당 날짜에 실제로 **사전 고정했던 v2 `KRX_OPEN` 가상 목록**만 읽습니다.
- 고정 목록의 종목 중 `VENUE_FIRST_TRADE`라는 **소프트웨어 근거로 가상 진입한 종목** 수,
  근거가 없어 아직 가상 진입하지 않은 종목 수, 가상 보유/청산 건수를 표시합니다.
- 근거 해시, 날짜, KRX 정책, 모드, 고정 목록 종목·키의 일관성을 검증합니다. 서로 다른
  `DEMO` / `MOCK` / `REAL_QUOTES` 모드의 개인 DB를 섞지 않습니다.
- 미고정 날짜는 목록을 소급 생성하거나 실제 거래를 추측하지 않습니다. 과거 v1 NXT 우선
  목록은 새 v2 KRX 개장 정책으로 소급 판정하지 않습니다.
- 5종목씩 페이지로 조회하며, 페이지가 지나쳐도 신규 기록이나 주문을 만들지 않습니다.

## 상태 해석

| 상태 | 정확한 의미 |
| --- | --- |
| 첫 거래 근거 미첨부 · 진입 미확인 | 해당 고정 목록의 **가상 진입 기록이 없음**. 실제 주식 거래가 없었다는 뜻이 아님 |
| 가상 진입 근거 기록 있음 · 가상 보유 | 저장된 가상 장부에 지정 형식의 첫 거래 근거/가상 포지션이 있음 |
| 가상 진입 근거 기록 있음 · 가상 청산 | 가상 진입 기록과 가상 청산 시각이 저장되어 있음 |

**중요:** `evidence_hash`는 저장한 원문 내용의 변조 여부를 점검하는 데 사용할 수 있는
프로그램 필드로, 그 자체가 Kiwoom·KRX로부터 발급한 공식 체결 인증서는 아닙니다.
외부 원본 체결 자료의 연속성·원문 출처·페이지 누락 여부가 검증되지 않은 상태라면
`VENUE_FIRST_TRADE` 필드가 있더라도 *진짜 첫 체결가인지 인증됐다고 말하면 안 됩니다*.

이번 기능은 **첫 거래가격 자동 수집을 구현한 것이 아닙니다**. 기존 근거 기록의
존재·일관성·공백만 확인하며, 실제/모의 주문 API, 시세 다운로드, 가상매수,
가상매도, 개인 파일 수정 등을 수행하지 않습니다. 계좌가 매수했는지는
`/추천대조` 등 별도의 사용자가 보유한 체결 증거로 확인해야 합니다.

## 다음 실증 단계

1. 권한이 확인된 KRX/Kiwoom 공식 첫 체결 원문과 페이지 완전성, 개장 시각 및 종목 시장을 검증하는
   **독립적인 수신 근거**를 확보하기.
2. 취득 실패/응답 지연/종목별 최초 거래 시각 불명 시 가상 진입을 만들지 않기.
3. 합성 오프라인 검증 뒤 실제 Windows GUI·인증된 텔레그램 왕복과 키움 **모의계좌만**
   명시적으로 허가받아 검증하기. 실계좌 주문은 계속 금지합니다.

합성 데이터 오프라인 검사 통과는 위의 실제 운영 검증을 대체하지 않습니다.
