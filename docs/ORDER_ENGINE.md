# 주문 엔진 1차 구현 — 오프라인 전용

## 현재 가능한 것

- `OrderEngine`은 `SIMULATED` 환경만 받으며 HTTP나 인증정보를 사용하지 않습니다.
- 지정가 매수·매도, 총수량/가격 정정, 남은 수량 취소를 영속 기록합니다.
- 현금은 체결 때만 바뀝니다. 접수는 체결이 아닙니다. 미체결 주문은 현금/주식을 예약합니다.
- 부분체결의 누적 수량/금액 차이만 원장에 적용하므로 같은 체결 응답이 반복돼도 중복 차감하지 않습니다.
- 요청 번호를 먼저 DB에 기록하고 서버를 호출합니다. 같은 번호·같은 내용은 재전송하지 않고 기존 상태를 반환하며 내용이 다르면 거부합니다.
- 응답 유실·잘못된 체결은 `UNKNOWN`(결과 확인 필요)으로 남기고 새 주문/정정/취소를 막습니다. 조회(`reconcile`)만 가능하며 주문을 다시 보내지 않습니다.
- `SimulatedBroker`는 별도 SQLite에 가짜 주문·현금·보유 수량을 저장합니다. 체결은 테스트가 명시적으로 넣어야 하며 현재가·고가/저가만으로 체결을 만들어내지 않습니다.

| 상태 | 사용자에게 설명할 뜻 |
|---|---|
| SENDING | 요청을 기록하고 보내는 중 — 다시 보내지 않음 |
| OPEN | 접수됐지만 아직 체결 없음 |
| PARTIAL | 주문 일부만 체결됨 |
| FILLED | 주문 전량 체결됨 |
| CANCELED | 남은 미체결 수량 취소, 이미 체결된 수량은 유지 |
| REJECTED | 서버가 명확히 거부, 체결로 취급하지 않음 |
| UNKNOWN | 전송/체결 결과 확인 필요, 새 주문 중단 |

정정의 수량은 남은 수량이 아니라 **총 주문 수량**입니다. 이미 체결된 수량 이하로
줄이지 않으며 잔여 수량 제거는 취소를 사용합니다. 실제 증권사 API의 정정 규칙과는
별도이므로 향후 어댑터가 이를 정확히 변환해야 합니다.

## 직접 시험하기

`python -m app.order_demo` 또는 앱의 **연구·고급 메뉴 보기 → 연결 설정 → 가짜 서버로 주문 흐름 시험**.
임시 폴더에서 가짜 매수·부분체결·정정·취소·매도와 재시작 후 원장 일치를 확인합니다.
현재 앱의 「연습으로 1주 사기」는 기존 연습 기능이며 이 신규 엔진과 아직 연결하지 않았습니다.

## 가격과 거래시간 기준

- 화면·알림의 현재가는 API의 마지막 제공 시세입니다. 정규장 종가로 확정하지 않습니다.
- API 시세 시각과 수신 시각을 구분합니다. 수신한 시간이 최근이라는 사실만으로 가격이 새 시세가 되지 않습니다.
- 시각만 보고 KRX/NXT 체결 거래소를 추정하지 않습니다. 공급자가 거래소를 확정하지 않으면 미확인입니다.
- `TradingCalendar`는 명시적으로 등록한 거래일만 사용합니다. 날짜 자료가 없으면 닫힌 것으로 처리합니다. 평일을 자동으로 거래일로 만들지 않습니다.
- 주문 시험에 사용하는 구간은 KST, 시작 포함/종료 제외입니다. KRX 정규장 09:00~15:30, NXT 08:00~08:50 / 09:00:30~15:20 / 15:40~20:00입니다. 호가접수 구간 전체·시간외 주문·예약 주문은 지원하지 않습니다.
- 날짜·시장별 예외 구간으로 임시 개장시간을 덮어쓸 수 있습니다. 실제 운영 전 공식 거래일과 예외 운영 자료를 연결해야 합니다.
- 거래시간 밖의 주문은 거부하며 다음 거래일에 자동으로 실행하지 않습니다.

공식 구간 확인(2026-10-17): [KRX 시장 운영](https://regulation.krx.co.kr/contents/RGL/03/03020401/RGL03020401.jsp), [NXT 거래제도](https://www.nextrade.co.kr/transactionSys/content.do).

## 아직 증명하지 않은 것 / 후속 단계

- 키움 모의·실계좌의 주문 접수·체결·잔고 일치. 실제 API 어댑터 자체가 없습니다.
- 한도/권한/일회용 확인/긴급 중지/단일 실행 잠금은 단계 3~4에서 완성합니다.
- `recover()`는 이전 작업자가 종료된 뒤 하나의 소유자만 호출해야 합니다. 실행 중인 작업에 임의로 호출하면 안 됩니다. `SENDING`을 `UNKNOWN`으로 바꾸며 재전송하지 않습니다.
- 응답 불명 상태에서 서버 조회에 주문이 없어도 미접수라고 단정하지 않습니다. 자동으로 중단을 풀지 않습니다. 정정·취소 성공이 확정되지 않으면 계속 중단합니다.
- 예시는 수수료·세금·슬리피지가 없습니다. 계좌의 실제 주문가능금액·예약·체결/정산과 동일하다는 뜻이 아닙니다.
- 키움 모의 환경의 지원 시장·주문 유형, 실제 호가단위, 부분 취소·정정 접수/완료 구분은 어댑터 단계에서 별도 검증합니다.
- 가짜 서버는 단일 엔진/원장이 관리하는 시험용입니다. 다른 클라이언트의 독립 주문, 계좌 외부 입출금, 체결 정정/취소 등은 아직 모델링하지 않습니다.

공식 거래 가능 시간에 모의 검증 후, 별도 승인한 제한적 실계좌 시험으로 넘어갑니다.
