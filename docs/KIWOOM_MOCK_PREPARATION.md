# 키움 모의 연결 준비 — 단계 5 진행 중

현재는 **요청 형식·모의 통신·전송 기록·계좌/체결/잔고 조회 대조를 오프라인에서 검증한 상태**입니다.
실제 모의 주문·체결 검증 완료가 아닙니다. 화면과 텔레그램은 계속 가상 연습 엔진만 씁니다.

## 이번 구현

`app/kiwoom_mock_contract.py`는 통신·인증 없이 요청 자료만 만듭니다.
목적지는 모의 도메인으로 고정하고 KRX 보통 지정가 매수/매도만 준비합니다.
정정 수량은 기존 엔진의 전체 주문 수량과 구분한 **잔량 기준 수량**입니다.
정정/취소 수량 0은 잔량 전부라는 공식 규칙을 표현합니다.
정정·취소의 새 주문번호와 모주문번호를 각각 보관하며 접수 응답은 체결/취소 완료가 아닙니다.

미체결·체결·보유 목록은 한 페이지씩 허용 항목만 추출하며 계좌번호·서버 메시지는 내보내지 않습니다.
연속 조회 여부가 없거나 다음 페이지 키가 누락되면 완전한 조회로 처리하지 않습니다.
값은 아직 원문 문자열이며, 합산 체결량·최종 주문 상태로 해석하지 않습니다.
예수금 조회 요청은 준비했지만 예수금·주문가능금액·결제예정금을 하나의 현금으로 합치지 않습니다.

## 모의 통신·전송 기록 추가

`app/kiwoom_mock_transport.py`는 모의 도메인만 사용합니다. 명시적 로그인 전에는 요청하지 않고,
인증정보와 토큰은 메모리에만 둡니다. 자동 재시도·자동 토큰 갱신·리디렉션을 사용하지 않습니다.
기본 통신 세션은 환경 프록시 설정을 사용하지 않으며 호출 시작 간격을 최소 1.1초로 제한합니다.
정의되지 않은 API·추가 필드·시장가 등 준비 범위 밖 요청을 차단합니다.
목록은 모든 페이지를 읽어야 반환하고 반복 커서·페이지 제한 초과·불완전 응답이면 중단합니다.

`app/kiwoom_mock_journal.py`는 전송 직전에 SENDING 기록을 확정합니다.
정상 접수는 ACKNOWLEDGED, 명확한 거절은 REJECTED, 통신 실패·모순 응답은 UNKNOWN입니다.
같은 요청 번호의 재호출은 저장된 결과만 반환하며 다른 내용으로 재사용할 수 없습니다.
UNKNOWN/SENDING이 있으면 새 요청을 차단하고 자동 해제나 재전송 기능을 제공하지 않습니다.
프로그램 종료 후 남은 SENDING도 다음 열기에서 UNKNOWN으로 변경합니다.
OS 잠금으로 전송 중 다른 실행이 기록을 복구하거나 주문을 동시에 보내지 못하게 합니다.
정정·취소는 기록된 최신 접수 번호만 대상으로 삼고 원주문까지 번호 계보를 보존합니다.
번호 중복·모주문 불일치도 UNKNOWN으로 차단하며 ACKNOWLEDGED는 취소 완료가 아닙니다.

이 기록은 모의 전용 폴더의 별도 DB에 두어야 합니다. 다른 기능의 DB는 거부하며
가상 연습 엔진의 SIMULATED 제한은 유지합니다. 프로필은 계좌번호가 아닌 무작위 로컬 식별자입니다.
**프로필 식별자 일치는 실제 인증 계좌 일치의 증명이 아닙니다.** 연결된 모의 계좌 대조는 남아 있습니다.
기본 화면·텔레그램에는 이 통신부를 연결하지 않았습니다. 개발 중 인증·주문을 실행하지 않았습니다.

## 계좌·체결·잔고 조회 대조 추가

`app/kiwoom_mock_review.py`는 읽기 전용입니다. 사용자가 별도로 지정한 모의 계좌와
계좌번호조회(ka00001) 결과를 처음과 끝에 비교합니다. 원 계좌번호는 결과·오류에 남기지 않으며
계좌 구분용 해시도 기본 표시에서 숨깁니다. 계좌번호나 인증정보를 저장소에 기록하지 않습니다.

같은 한국 날짜·인증 세션·프로필에서 예수금/보유/체결/비용/미체결 전체 조회를 두 번 하고,
정규화한 결과가 같아야 반환합니다. 중간에 계좌·인증·날짜·조회값이 달라지면 중단합니다.
이는 순차 조회 사이의 안정성 검사이며 증권사의 원자적 스냅샷이나 최종 결제를 증명하지 않습니다.
날짜 입력이 없는 ka10076 비용 조회 때문에 현재는 한국 날짜의 오늘 자료만 대조합니다.

체결번호를 제공하는 계좌별주문체결현황(kt00009)을 추가했습니다.
주문번호+체결번호로 중복을 제거하고 같은 번호의 가격·수량 등이 다르면 차단합니다.
부분체결마다 체결량×체결가를 합산해 매수/매도 **비용 전 체결금액**을 따로 계산합니다.
예수금, 주문가능금액, 100% 증거금 주문가능금액, D+1/D+2 예수금을 구분합니다.
보유 수량과 매도 가능 수량도 따로 대조하며 음수 수량·중복 보유·누락 금액을 0으로 바꾸지 않습니다.

ka10076의 `tdy_trde_cmsn`/`tdy_trde_tax`는 당일 수수료/세금으로 설명되어 있습니다.
체결별 비용이라는 근거 없이 더하지 않고 주문별 조회 관측값으로 보존·비교합니다.
같은 비용 관측값의 반복은 제거하지만 서로 다른 값은 그대로 남깁니다.
따라서 현재 비용 후 현금흐름·수익률을 계산하지 않으며 총비용 귀속 확인은 남아 있습니다.

독립된 장부의 예상값과 조회 날짜·계좌·잔고·체결·비용 관측값·미체결을 비교할 수 있습니다.
관측값 일치와 거래 재개 가능 여부는 별개입니다. 대조 결과는 항상 주문 가능 상태를 False로 두며
전송 기록의 UNKNOWN을 해제하거나 기존 엔진·텔레그램에 주문 기능을 연결하지 않습니다.

## 영속 체결 장부와 비용 근거

`app/kiwoom_mock_ledger.py`의 장부는 확인된 계좌 구분값에 묶인 모의 전용 DB입니다.
`collect_into`로 완전하고 안정된 조회만 저장합니다. 기존 연습 DB·전송 DB와 공유할 수 없습니다.
거래일+주문번호+체결번호로 체결을 저장해 다음 날 주문번호가 재사용돼도 섞이지 않습니다.
재시작·역순 재조회·같은 체결 반복을 처리하고, 기존 체결의 누락·수정은 갱신 전체를 취소합니다.
최신 계좌 관측값은 거래일별로 보관하고 체결은 누적 보존합니다.

주문별 비용을 기록하려면 외부에서 독립적으로 확인한 수수료·세금 합계, 해당 체결 수량·금액,
근거 문서 해시·근거 항목 식별자가 필요합니다. 같은 근거 항목을 다른 주문에 중복 적용할 수 없고,
기존 확인을 다른 값으로 덮어쓰지 않습니다. 원 문서·개인 파일 경로·계좌번호는 저장하지 않습니다.
이는 **호출자가 확인한 비용을 기록하는 기능**으로 문서의 진위·비용 귀속을 자동 검증하지 않습니다.
현재 비용 입력 UI나 실제 명세서 가져오기는 없으며 가짜 증거로만 시험했습니다.
ka10076의 관측값은 이 확인을 대신하지 않습니다. 합성 비용 근거는 SYNTHETIC_TEST로 표시합니다.

비용은 정확히 그 체결 집합에만 적용합니다. 추가 부분체결이 들어오면 이전 비용을 적용하지 않고,
새로운 체결 수량·금액과 새로운 근거로 다시 확인해야 비용 후 매매 현금흐름을 계산합니다.
매수는 -(체결금액+수수료+세금), 매도는 체결금액-수수료-세금입니다.
이 값은 인출가능금액·주문가능금액·결제된 예수금이 아닙니다.

`project_order`는 기존 엔진의 OrderRequest와 체결 장부를 읽기 전용으로 연결합니다.
종목·방향·지정가·주문량을 대조하며 체결 근거 없음/부분체결 관측/전체체결 관측을 구분합니다.
단일 증권사 주문번호만 지원하고 정정·취소 계보 합산은 아직 연결하지 않았습니다.
기존 OrderEngine의 SIMULATED 제한은 유지하며 이 결과로 주문하거나 현금·보유를 변경하지 않습니다.

## 거래일별 접수와 정정·취소 계보 합산

접수 장부는 전송 전에 한국 거래일을 저장하고 `(거래일, 주문번호)`를 구분합니다.
다음 날 같은 주문번호가 나와도 충돌하지 않으며 지난날 주문을 오늘 정정·취소 대상으로 삼지 않습니다.
날짜 없는 옛 기록은 거래일을 NULL로 유지하는 형태로 이관합니다. 기존 요청의 재호출은 저장 결과만
반환하고, 날짜 미확인 기록이 남아 있으면 새 요청을 차단합니다. 이관은 한 트랜잭션으로 수행합니다.
전송 도중 날짜·인증 세션이 바뀌면 UNKNOWN으로 남겨 재전송하지 않습니다.

접수 전에 `bind_account`로 독립적으로 확인한 모의 계좌 구분값을 연결할 수 있습니다.
접수 후 기존 미연결 기록의 계좌를 추정해 지정할 수 없으며 다른 계좌로 바꿀 수 없습니다.
이 연결 자체가 현재 인증 계좌를 검증하는 기능은 아닙니다. 주문 전 재검증은 여전히 남아 있습니다.

`app/kiwoom_mock_chain.py`는 계좌 구분값이 같은 두 장부의 읽기 전용 연결입니다.
처음 주문부터 정정·취소 요청까지 연결된 번호를 따라 체결 수량·금액을 합산합니다.
각 주문번호의 종목·방향·지정가·명시적 수량 상한을 확인하고 중복 체결번호·미확인 요청·끊긴 계보·
기록 밖 후속 체결이 있으면 합산하지 않습니다. 원자료의 체결번호가 서로 다른 주문에서 겹치면
독립 체결인지 중복 표기인지 추정하지 않고 차단합니다.

비용은 체결이 있는 모든 번호에 현재 체결 집합과 일치하는 근거가 있고 근거 종류가 같을 때만
합산합니다. 하나라도 비용이 미확정이거나 합성/모의 명세서 근거가 섞이면 비용 후 합계는 미확정입니다.
잔량 전부 정정(수량 0)을 무제한 체결량으로 취급하지 않습니다. 다만 시점별 체결과 증권사 상태가
없으므로 정확한 최종 목표 수량이나 남은 수량을 계산하지 않으며 취소 완료도 판정하지 않습니다.
합산 결과는 CHAIN_OBSERVATIONS_ONLY이고 주문 가능 상태는 항상 False입니다.

## 연결 전에 남은 작업

`app/kiwoom_mock_status.py`는 실제 연결 없이 주문 알림(00)을 검사하고 쉬운 표시 자료를 만듭니다.
취소 상태 enum은 공식 913 항목(접수/체결/확인/취소/거부)을 따릅니다. 현재 모의 계좌·세션,
KRX·매수/매도 구분·원주문·최근 시간을 대조합니다. 공식 알림에는 거래일 없이 HHmmss만 있어
날짜를 넘긴 세션은 거부하며, 이것만으로 최종 잔량이나 취소 완료를 확정하지 않습니다.
취소 알림과 현재 조회된 잔량을 별개로 표시하고 알림 이후의 재조회가 필요하다고 안내합니다.
실시간 소켓 연결·자동 재연결·실제 알림 검증은 구현/실행하지 않았습니다.

돈 표시는 두 주문가능금액의 보수적인 최솟값을 사용하며, 미체결 추정 금액을 다시 빼지 않습니다.
내일/모레 예수금을 현재 금액에 더하지 않고, 독립 기록 불일치·미확인 주문·음수 가능 금액은
금액 표시를 보류합니다. 매도 주문 예약 수량도 보유/매도가능수량과 구분합니다.
이 자료는 아직 GUI에 연결하지 않았으며 모든 표시 결과의 주문 가능 상태는 False입니다.

1. 읽기 전용 계좌 대조 결과를 모의 프로필·전송 기록에 영속 연결하고 로그인 변경 시 재검증합니다.
   현재 조회 대조는 주문 전 필수 계좌 확인·확인 화면·주문 한도·거래일 검사를 대신하지 않습니다.
2. 읽기 전용 계보 합산에 증권사의 정정/취소 완료 상태와 시점별 잔량을 연결하고 조회 기반 미확인 해소 절차를 구현합니다.
   주문 응답 유실 시 자동 재전송·시간/종목만으로 추정 매칭하지 않습니다.
3. 실시간 체결·비용 근거 자동 검증·결제/예약 금액을 연결합니다. 비용 근거 기록 자체는 실제 비용 확인의 증명이 아닙니다.
   체결 조회의 `ord_no`는 해당 번호보다 과거 내역을 찾는 기준이며 정확한 번호 필터가 아닙니다.
4. 공식 거래일/특별 운영시간, 종목별 호가 단위·가격 범위·모의 지원 범위를 검증합니다.
5. 그 후 기존 엔진의 SIMULATED 전용 잠금을 모의 전용 경로로 확장하고 별도 기록 폴더를 씁니다.
