# 텔레그램에서 키움 모의 매수·매도·정정·취소

실제 돈 거래와 가짜 서버 연습 주문과는 별도의 **키움 모의투자** 기능입니다.
이번 구현은 가짜 HTTP·소켓과 임시 DB로 검증했습니다. 실제 모의 주문은 실행하지 않았습니다.

## 집 PC에서 오늘 사용할 때만 켜기

1. 키움 모의투자 모드와 모의 전용 키를 저장합니다.
2. 모의 HTS에서 오늘 거래 가능한 날인지 확인합니다.
3. `오늘 텔레그램 키움 모의 주문 허용`과 `모의 HTS에서 오늘 거래 가능한 날임을 확인했어요`를 켭니다.
4. 모의 계좌번호를 입력하고 계좌 확인 → 알림 시작을 진행합니다.
5. 텔레그램 명령 수신을 시작하고 본인의 개인 대화에서 사용합니다.

기본값은 꺼져 있고 주문 허용은 저장하지 않습니다. 거래일 자료를 자동으로 추정하지 않으며,
사용자가 확인한 당일 평일의 KRX 정규 거래 시간(09:00~15:30)에만 요청을 받습니다.
모의 주문 허용은 끊김·중지·종료·거래 가능 시간 종료 때 해제됩니다.
`/모의재연결`은 조회·알림만 복구합니다. 주문을 다시 허용하려면 PC에서 중지 후 새로 설정해야 합니다.

## 텔레그램에서 주문하기

예시는 테스트용 코드입니다. 실제 모의투자 종목은 조회한 6자리 코드를 사용하세요.

1. `/매수 900001 1 1000` 또는 `/매도 900001 1 1000`을 보냅니다.
2. **키움 모의투자** 표시, 종목코드, 수량, 지정가와 금액을 읽습니다.
3. 2분 안에 안내받은 `/모의확인 코드`를 보냅니다. 전송 전 철회는 `/모의철회 코드`입니다.
4. `/주문상태`에서 접수 응답·거절·미확인 상태를 확인합니다.
5. `/잔고` → `/잔고결과`로 새 조회가 끝나면 `/주문상태`에서 조회된 미체결·부분체결·체결 수량을 봅니다.

종목명 입력, 시장가, 장 마감 예약 주문은 지원하지 않습니다.
조회된 남은 주문이 사라졌다고 취소 완료로 판단하지 않습니다.
확정되지 않은 최종 상태와 비용·결제는 별도로 확인해야 합니다.
`/모의철회`는 아직 전송하지 않은 확인을 철회하며 이미 전송한 주문을 취소하지 않습니다.

## 이미 보낸 모의 주문 정정·취소

1. `/잔고` → `/잔고결과`로 새 조회가 끝났는지 확인합니다.
2. `/미체결`에서 최신 모의 주문번호와 남은 수량을 확인합니다. 과거 요청은 `/주문목록`에서 봅니다.
3. 조회 후 30초 안에 `/정정 주문번호 남길잔량 지정가` 또는 `/취소 주문번호`를 보냅니다.
4. 원주문·체결 수량·남은 수량·변경 내용을 읽고 2분 안에 `/모의확인 코드`를 보냅니다.
5. `/주문상태`에서 접수 결과를 확인하고 `/잔고`를 다시 조회해 남은 수량을 대조합니다.

예: `/정정 0000013 2 1100`은 아직 남은 수량 중 2주를 1,100원 지정가로 남기는 정정 요청입니다.
수량 증가는 지원하지 않습니다. `/취소 0000013`은 조회 당시 남은 수량 전부를 명시적 수량으로 취소 요청합니다.
0으로 전부를 뜻하게 하거나, 일부만 취소하는 입력은 지원하지 않습니다.
본인이 이 프로그램에서 오늘 접수한 최신 주문번호만 사용할 수 있습니다.
정정 후에는 새 주문번호를 사용해야 합니다. 거절된 정정은 원래 최신 주문번호를 다시 조회합니다.

확인한 뒤 추가 체결·잔량 변화·인증 변경·중지·만료가 생기면 전송을 차단합니다.
수량을 자동으로 줄이거나 새 확인 없이 다시 보내지 않습니다.
정정 매수는 기존 예약을 중복 차감하지 않고 추가 필요 금액과 1% 여유를 대조합니다.
매도 정정은 이미 예약된 잔량과 보유·매도 가능 수량을 함께 확인합니다.

취소 접수 응답과 최종 취소 완료는 다릅니다. 잔량이 조회되지 않아도 `최종 취소 미확인`으로 표시합니다.
최종 취소·비용·결제의 독립 대조는 후속 검증입니다. 당일 취소 접수 뒤에는 새 주문·정정을 차단하며,
이 화면에 최종 상태를 확인했다고 표시하거나 잠금을 해제하는 기능은 아직 없습니다.
모의 HTS/MTS에서 최종 상태를 확인해야 합니다. 다른 확인된 주문의 취소 요청은 별도 한도 안에서 가능합니다.

## 내 주문 찾기

`/주문목록`은 본인의 저장된 모의 요청을 최근 순으로 5개씩 표시합니다.
다음 기록은 `/주문목록 2`처럼 페이지 번호로 봅니다. 연결 종료 뒤에도 접수 번호와 마지막 관측 시각을
볼 수 있지만 최신 증권사 조회는 아닙니다. 확인 코드는 목록에 표시하지 않습니다.

`/잔고` → `/잔고결과` 완료 뒤 30초 안에 `/미체결`을 보내면 같은 연결에서 조회한 내 당일 최신 주문번호와
남은 수량을 보여줍니다. 오래된 조회·인증 변경은 새 조회를 안내합니다. 외부 주문·다른 사용자 주문·
정정 전 번호는 표시하지 않습니다. 목록에 없다는 사실이 체결·최종 취소 완료를 뜻하지는 않습니다.
목록 명령은 추가 증권사 통신이나 주문 전송, 잠금 해제를 하지 않으며 `/중지` 뒤에도 조회할 수 있습니다.
실제 정정·취소 요청 때는 기존 내용 확인·새 조회 대조·주문 제한을 모두 다시 적용합니다.

## 취소 알림을 받은 뒤 대조하기

`/모의상태`에 취소 처리 알림이 보이면 `/잔고`를 요청하고 `/잔고결과`에서 완료를 확인하세요.
그다음 `/주문상태`에서 `취소 알림 뒤 새 조회 대조`와 다음 결과를 볼 수 있습니다.

- 조회된 남은 주문은 없어요
- 남은 주문이 있어요
- 취소 요청이 거절됐어요
- 취소 확인 중

같은 인증·모의 계좌·알림 연결에서 받은 최근 2분의 알림만 사용합니다.
알림 수신 후에 시작한 새 전체 조회만 대조하며, 이미 요청한 조회를 재사용해 추가 HTTP 조회는 하지 않습니다.
알림이 조회 중 도착했거나 먼저 조회했다면 다시 `/잔고`를 요청해야 합니다.
오래된 알림·인증 변경·연결 끊김·계보 불일치는 정상 대조 기록으로 남기지 않습니다.
대조 요약은 모의 전용 장부에 중복 없이 보관하고 알림 원문이나 계좌번호는 보관하지 않습니다.
메모리의 취소 알림은 최대 20개이며 연결 종료·재연결 시 지웁니다.

이 결과는 알림과 조회가 맞는 범위의 관측입니다. 최종 취소·비용·결제 완료나 새 주문 허용을 뜻하지 않습니다.

## 모의 긴급중지와 별도 재개

모의 주문 연결이 준비된 상태에서 `/긴급중지`를 보내면 새 전송을 막고 대기 중인 확인·전송 요청을
철회합니다. 긴 잔고 조회의 종료를 기다리지 않고 전송 차단 신호를 먼저 설정하며 재시작 후에도 유지합니다.
이미 전송 중이거나 접수된 주문을 증권사에서 취소하는 명령은 아닙니다.
모의 HTS/MTS와 `/주문상태`에서 이미 보낸 주문을 확인해야 합니다.

사용자가 요청한 긴급중지만 다시 허용하려면 다음 순서로 진행합니다.

1. 중지 뒤 `/잔고` → `/잔고결과`로 새 조회를 끝냅니다. 기존 조회를 재사용하지 않습니다.
2. 조회 완료 후 30초 안에 `/모의재개`를 요청합니다.
3. 안내된 시간 안에 `/모의재개확인 코드`로 별도 확인합니다.

새 주문은 이후에도 `/매수`·`/매도` 등으로 새 내용을 만들고 별도로 확인해야 합니다.
중지 때 철회된 주문은 복구하지 않습니다. 새 중지·다른 조회·수신 종료·재시작은 이전 재개 코드를 무효화합니다.
당일 거래 가능 시간·PC의 기존 모의 허용·현재 인증/계좌가 유효해야 합니다.
기록 충돌·미확인 전송·진행 중 처리·조회 대조 대기·최종 취소 미확인이 있으면 재개하지 않습니다.
`/모의재개`는 이 금융 기록 차단이나 실계좌 잠금을 해제하는 기능이 아닙니다.
연결을 종료했거나 원격 재연결했다면 PC에서 당일 연결·허용을 다시 설정해야 합니다.

가상 연습 모드의 `/긴급중지`는 기존 가짜 서버 연습 기능이며 키움 모의 중지 기록과 별개입니다.

## 차단 이유 확인

`/주문점검`은 차단 이유와 다음 확인 순서를 보여줍니다. 증권사 조회나 주문 전송을 하지 않고
로컬 기록만 읽으므로, 모의 잔고 조회 작업 중에도 점검을 요청할 수 있습니다.

| 표시 | 의미와 처리 |
| --- | --- |
| 기록 충돌로 차단 | 이전 체결의 누락·변경, 주문 수량/방향 불일치, 계보 또는 조회 연결 충돌. 대기 요청을 철회하고 재시작 뒤에도 차단을 유지합니다. |
| 미확인 전송으로 차단 | 주문이 전달됐을 수 있습니다. 같은 주문을 다시 보내지 말고 모의 HTS/MTS에서 확인합니다. |
| 새 조회 대조 대기 | 당일 접수 기록과 조회를 아직 맞추지 못했습니다. `/잔고` 새 조회가 같은 기록과 일치하면 이 대기 표시만 갱신합니다. |
| 최종 취소 대조 대기 | 취소 접수·잔량 조회만으로 완료를 판정하지 않습니다. 당일 새 주문·정정을 계속 차단합니다. |

기록 충돌 차단에는 자동 해제나 수동 해제 명령이 없습니다. 이후 정상 자료가 조회되거나 PC에서 다시 허용해도
해제하지 않습니다. 독립 근거 확인과 해제 절차는 후속 개발·실제 검증 대상입니다.
차단이 없다는 점검 결과도 실제 거래 검증 완료나 주문 가능 보장이 아닙니다.
원문 응답·계좌번호·키·확인 코드는 점검 답장에 넣지 않습니다.

## 작은 한도와 실패 처리

- 한 주문 최대 10주·10만원, 하루 매수·매도·정정 합산 최대 3회·20만원입니다.
- 취소는 금액·신규 주문 횟수 한도와 별도로 하루 10회까지 요청합니다. 거절·실패도 횟수에 포함합니다.
- 거절·전송 전 확인 실패·미확인 처리도 사용한 일일 한도를 돌려주지 않습니다.
- 전송 직전에 전체 계좌·잔고를 두 번 조회하고 인증·계좌·날짜를 대조합니다.
- 기존 미체결 주문이 있거나 매도 가능 수량이 부족하면 새 매수·매도를 차단합니다.
- 매수는 조회된 주문 가능 금액에서 주문금액의 1% 여유까지 요구합니다. 이는 실제 비용 계산이 아닙니다.
- 전송 시도는 한 번이며 결과 미확인 또는 중단 흔적이 있으면 새 주문을 차단합니다. 재전송하지 마세요.
- `/중지`와 수신 종료는 대기 확인·전송 대기 요청을 철회합니다. 이미 전송 중이거나 접수된 주문의 취소 명령은 아닙니다.
- 프로그램·수신 재시작은 과거 확인 코드를 무효화하고 처리 중이던 주문을 자동으로 재전송하지 않습니다.

모의 전용 로컬 기록에 주문 내용·일일 한도·접수 상태를 보관합니다. 키·원문 계좌번호는 넣지 않고
주문 대기 기록에는 확인 코드 해시를 보관합니다. 텔레그램 답장 기록에는 코드가 포함된 안내가 남을 수 있습니다.
이 기록을 지우거나 바꿔 잠금을 우회하지 마세요.
실제 계좌 주문 경로와 연결하지 않았으며, 실계좌 주문 잠금은 유지됩니다.
