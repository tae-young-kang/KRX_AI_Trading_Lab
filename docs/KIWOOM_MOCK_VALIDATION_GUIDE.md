# 모의 연결은 어디까지 확인됐나요?

현재 단계는 개발 순서의 **5단계 진행 중**입니다.
가짜 통신을 사용하는 오프라인 검사와 실제 키움 접속 검증은 다릅니다.
이 안내를 추가하면서 실제 프로그램·텔레그램·증권사 접속을 실행하지 않았습니다.

## 텔레그램에서 확인하기

집 PC에서 모의 계좌 확인과 알림 시작을 한 뒤 `/모의점검`을 보내세요.
이번 프로그램 실행 중 관측한 연결 시작·계좌 조회·알림 등록·잔고 재조회·연결 종료를 볼 수 있습니다.
기록은 메모리에 최대 20개만 두고 최근 10개를 표시합니다. 종료하면 사라집니다.
재연결할 때 현재 연결의 조회·알림 횟수는 새로 셉니다.
계좌번호·인증값·원문 서버 응답·금액은 이 점검 기록에 넣지 않습니다.

이 기록은 관측을 확인하기 위한 안내이며 독립적인 체결 증명이나 감사 장부가 아닙니다.
`/모의상태`와 `/잔고결과`에서 조회 시각을 확인하세요.

## 프로그램을 껐다 켠 뒤 기록 보기

`/모의기록`은 집 PC에 저장한 최근 모의 관측 10개를 보여줍니다. 최대 1,000개를 보관하며
연결 시작·계좌 조회·알림 등록·새 조회·재연결 요청·연결 종료와 모의 요청의 접수/거절/미확인/실패,
기록 충돌·긴급중지 요청을 고정된 문구로 기록합니다. 적용 전 과거 이력은 복원하지 않습니다.
같은 PC의 모의 관측 기록이므로, 이전에 설정했던 텔레그램 사용자의 활동도 시각·종류만 보일 수 있습니다.

현재 실행과 이전 실행을 구분합니다. 이전 관측이 있어도 현재 연결·잔고·주문 허용을 복원하지 않습니다.
새 상태는 `/모의상태`, 주문 차단 이유는 `/주문점검`, 본인 주문번호는 `/주문목록`에서 확인하세요.
이 명령은 증권사에 접속하거나 주문하지 않습니다. `/중지` 후에도 허용 개인 사용자에게 응답합니다.

로컬 파일은 `kiwoom_mock_watch/observations.db`이며 버전 관리에서 제외합니다.
무작위 실행 구분값·한국 시각·고정 사건 코드만 저장하고 계좌번호·키·텔레그램 사용자 번호·종목·금액·
주문번호·서버 응답 원문은 저장하지 않습니다. 파일을 읽을 수 없으면 복구를 안내하고 원문 오류를 보내지 않습니다.
저장 실패는 누락 가능성으로 표시합니다. 연결 중 비정상 종료·기록 오류로 빠진 사건이 있을 수 있으며,
이 기록은 체결·취소 완료·비용/결제·잔고 일치를 증명하는 감사 장부나 주문 잠금 해제 근거가 아닙니다.

## 실제 접속 확인 순서 — 아직 실행하지 않음

1. PC에서 **키움 모의투자** 모드를 저장하고 모의 전용 키를 등록합니다.
2. 허용된 본인 개인 대화로 텔레그램 수신을 시작합니다.
3. 모의 계좌 확인 후 별도로 알림 시작을 누릅니다.
4. `/모의점검`에서 계좌 조회와 알림 등록 관측을 확인합니다.
5. `/잔고`를 보낸 뒤 `/잔고결과`로 조회 완료·시각·보유 수량을 확인합니다.
6. 키움 모의 HTS/MTS의 같은 계좌에서 보유·미체결·금액의 의미와 수치를 별도로 대조합니다.
7. 조회 실패·연결 끊김이면 이전 잔고가 오래된 값으로 표시되는지 확인합니다.
8. 당일 원격 복구를 PC에서 허용한 경우, 끊긴 뒤 `/모의재연결` 요청 한 번으로
   새 계좌 조회와 알림 등록이 이뤄지는지 확인합니다. 실패 뒤 자동 재시도가 없어야 합니다.

네트워크 변경·복구 시험은 활성 주문 없이 진행해야 합니다.
본인이 아닌 사용자·그룹 대화에서는 점검 내용이 응답되지 않아야 합니다.
계좌번호나 키를 텔레그램으로 보내지 않습니다.

## 아직 증명하지 못한 것

### 다음 실제 모의 검증의 핵심 경로

추가 편의 기능보다 아래 경로의 실제 증권사 검증을 우선합니다. 현재는 가짜 HTTP/소켓으로
텔레그램 형식 요청 → 매수 접수 → 부분체결 조회 → 정정 → 추가 부분체결 → 잔량 취소 →
새 조회 → 긴급중지 → 로컬 기록 재개방까지 통합 검사했습니다. 실제 Telegram 서버 송수신이나
키움 체결을 증명하는 검사가 아닙니다. 취소 응답을 못 받은 경우에도 재전송하지 않는 것을 검사합니다.

1. 거래 가능한 날에 모의 HTS에서 동일 계좌·잔고를 먼저 확인합니다.
2. 집 PC에서 당일 모의 주문을 별도 허용한 뒤 허용된 개인 대화의 작은 지정가 요청을 확인합니다.
3. 접수 응답과 실제 체결을 구분해 주문번호·체결량·미체결·보유 수량을 모의 HTS와 대조합니다.
4. 부분체결이 실제 발생한 경우에만 남은 수량의 정정·취소와 새 번호를 대조합니다. 발생하지 않은
   부분체결을 확인했다고 기록하지 않습니다. 시험을 위해 주문을 반복하거나 조건을 자동 완화하지 않습니다.
5. `/잔고` → `/잔고결과` 뒤 `/모의자금`으로 예수금·주문 가능 금액·D+1/D+2 예상값을 구분합니다.
   미래 결제일 값을 현재 금액에 더하거나 조회된 주문 가능 금액에서 예약액을 또 빼지 않습니다.
   외부 주문 등 미체결 매핑을 확인하지 못하면 주문 가능 금액과 예약 추정액은 ‘대조 필요’입니다.
6. 거래 종료 뒤 수수료·세금·예약·결제와 취소의 최종 상태를 별도 근거로 대조합니다.

`/모의자금`은 이미 받은 조회만 읽습니다. 30초 초과·시계 역행·날짜 변경·주문 처리/알림·중지·
새 조회 진행 중에는 금액을 현재 값처럼 표시하지 않고 재조회를 안내합니다. 주문 허용과 별개입니다.
계좌 조회 시점의 금액 표시는 독립적인 자금 일치 판정이나 금융 차단 해제 기능이 아닙니다.
기존 UNKNOWN·기록 충돌·최종 취소 미확인 차단은 유지하며 강제로 해제하거나 기록을 지우지 않습니다.

### 현재 남은 검증

| 항목 | 현재 판단 |
| --- | --- |
| 계좌 조회·알림 연결·텔레그램 처리 | 오프라인 검사 통과, 실제 송수신 확인 필요 |
| 모의 매수·매도 접수와 체결 | 별도 당일 허용 전송 경로 구현, 실제 장중 검증 필요 |
| 정정·취소·부분체결 | 명령·계보·취소 알림 후 새 조회 대조 연결 구현, 실제 증권사 최종 상태 대조 필요 |
| 보유·미체결·주문 가능 금액 | HTS/MTS와 독립 대조 필요 |
| 수수료·세금·예약·결제 | 근거와 최종 금액 대조 필요 |
| 날짜 변경·재시작·장시간 운영 | 실제 운영 검증 필요 |
| 실제 돈 거래 | 잠금 유지, 별도 승인과 제한적 시험 필요 |

연결 성공이나 알림 수신은 실제 주문이 가능하다는 증명이 아닙니다.
이 점검 기능은 주문을 보내거나 주문 잠금을 해제하지 않습니다.
별도 모의 주문 기능은 [키움 모의 주문 안내](TELEGRAM_KIWOOM_MOCK_ORDERS.md)를 참고하세요.

## 다음 할 일 안내

/모의점검은 오늘 관측된 계좌·알림·새 조회 상태에 따라 다음 확인 한 가지를 먼저 안내합니다.
오늘 계좌 관측 없음→PC 모의 계좌 확인, 알림 관측 없음→알림 상태 확인,
오늘 새 조회 없음/30초 초과→/잔고와 /잔고결과, 최근 조회 관측→같은 모의 HTS/MTS 직접 비교입니다.
날짜 변경·시계 역행이면 이전 계좌/알림 관측을 오늘의 준비 상태로 쓰지 않습니다.
30초는 다음 확인 안내의 기준일 뿐 최신 잔고 보증·모의 체결 인증·주문 활성화 기준이 아닙니다.
이 안내는 상태를 읽기만 하며 조회/재연결/주문/잠금 해제를 자동 실행하지 않습니다.
