# 거래·추천 기록 백업

연습 기록 화면의 ‘현재 모드 기록 백업하기’를 누르고 저장할 폴더를 고릅니다.
현재 선택된 기록 DB의 SQLite 일관 사본을 새 krx-records-모드-구분값 폴더에 저장합니다.
기존 폴더를 덮지 않으며 완료한 사본은 records.db와 manifest.json 두 파일입니다.

원본의 WAL에 남은 확정 기록도 SQLite backup으로 포함하고, 사본만 단독 DB로 정리합니다.
원본 모드/기록은 바꾸지 않습니다. 사본의 quick_check·필수 기록 테이블·크기·SHA256을
확인한 뒤 새 폴더로 공개합니다. manifest에는 모드/생성시각/크기/해시만 기록합니다.
이 모드는 선택한 파일의 사용 맥락이며 과거 혼합 기록의 출처를 새로 인증하는 값은 아닙니다.

연결 키·settings.json·연구 DB·증권사 접수/체결 DB·텔레그램 수신 기록은 이 백업에 포함하지 않습니다.
따라서 전체 운영 복구용 백업은 아직 아닙니다. 파일에는 거래·추천 기록이 담기므로 개인 저장소에서 관리합니다.
verify_backup은 사본 검증만 하며 복원하거나 현재 기록을 덮지 않습니다.

연습 기록 화면의 **저장한 백업 확인하기**에서 `krx-records-...` 백업 폴더를 고르면
현재 선택된 모드와 백업의 모드가 일치하는지, 파일 크기·SHA256·DB 무결성 및
검색/연습 매매/추천 묶음 **건수**를 읽기 전용으로 확인합니다.
기록의 개별 내용은 표시하지 않으며, 이 검사만으로 모든 기록의 업무적 정합성이나
실제 계좌 체결 내역까지 확인한 것은 아닙니다.

검증 대상 폴더에는 `records.db`와 `manifest.json` 두 파일만 있어야 합니다.
WAL/SHM/저널/임의의 추가 파일 또는 심볼릭 링크가 들어 있으면 검증을 중단합니다.
파일이 손상되었거나 모드가 다르면 **복원하지 않고** 오류를 알립니다.
백업을 읽어도 현재 DB를 덮어쓰거나 증권사 API/매매 주문을 호출하지 않습니다.
복원 UI·전체 운영 자료 백업·기기별 복구 검증은 후속 작업입니다.

실제 프로그램/계좌를 실행한 검증은 하지 않았으며 자동 백업이나 외부 업로드 기능도 아닙니다.

2026-10-19 원격 개발 분기에서 구현. 독립 합성 SQLite 오프라인 검사 3개 통과.
전체 프로젝트 자동검사 및 실제 Windows GUI 조작 검증은 별도 확인이 필요합니다.


## 운영 기록 전체 묶음 백업과 새 폴더 복원 (오프라인 도구)

위 PC 버튼은 여전히 현재 모드 단일 DB 백업입니다. 아래 도구가 별도의 운영 기록 묶음입니다.
프로그램과 텔레그램/모의 수신을 모두 종료하고 프로젝트 폴더의 PowerShell에서 실행합니다.
`python`은 필요한 패키지가 설치된 프로젝트 Python입니다.

```powershell
python -m app.operating_backup backup "D:\개인백업"
python -m app.operating_backup verify "D:\개인백업\krx-operations-생성된번호"
python -m app.operating_backup restore "D:\개인백업\krx-operations-생성된번호" "D:\새복원폴더"
```

백업 저장 폴더는 미리 만들어 두고,복원 대상 폴더는 아직 존재하지 않아야 합니다.
기존 앱 자료 폴더를 덮어쓰지 않습니다. GUI/수신 OS 잠금이 잡혀 있으면 백업을 중단합니다.
이 업데이트 이전 버전의 GUI는 앱 전체 잠금이 없으므로 업데이트 후에도 먼저 모든 창을 직접 종료해야 합니다.
외부 SQLite 편집기/다른 수동 입력 도구도 종료하세요. DB별 일관 사본이며 여러 DB를 한 트랜잭션으로 인증하는 도구는 아닙니다.

포함 범위는 코드에 정한 운영 기록 파일입니다: 모드별 연습/추천,이전trading.db,연구·테마1,
조건 명령/조건 이력,실제 체결 입력,텔레그램/가짜 주문 서버,키움 모의 관측·요청·접수·체결·보호 기록,
날짜별 아침 가상 DB와 모의 기록용32자리 비밀 아닌 profile.id입니다.
아직 생성하지 않은 기록은 없으므로 포함하지 않습니다. 임의의 모든DB/파일을 재귀 백업하지 않습니다.
이전trading.db의 혼합 출처는 그대로 별도 보존하며 새 모드로 인증하거나 합치지 않습니다.

**연결 키·settings.json·.env·API 폴더·개인 CSV 내보내기·임의 파일은 제외**합니다.
운영 기록 자체에도 개인 거래 정보가 있으므로 개인 폴더에 보관하고 GitHub에 올리지 마세요.
파일별 상대 이름/크기/SHA256과 생성시각을 manifest에 기록하고,필수 테이블/quick_check·해시를 검증합니다.
사본만 DELETE 저널로 정리해 WAL/SHM 없이 복원할 수 있게 합니다. 원본 WAL에 확정된 기록도 포함합니다.
링크/경로 탈출/목록 밖 파일·저널/해시 변조/종류가 다른DB는 거절합니다. 복사 후 다시 검증하고 새 폴더로 공개합니다.

복원은 **프로그램 실행·연결·주문 재개를 하지 않습니다**. API키/계좌 설정도 복원하지 않습니다.
복원한 폴더를 사용할 때는 프로젝트를 켜기 전에 PowerShell에서 아래처럼 자료 폴더를 지정할 수 있습니다.

```powershell
$env:KOSPI_AI_DATA_DIR = "D:\새복원폴더"
```

이후 사용자 직접 시작 때 초기 설정/모드/연결을 다시 확인하고,이전 기록과 미확인 주문을 먼저 검토합니다.
모의 계좌의 이전 접수/체결이 현재 증권사 상태와 일치한다는 보장은 없으며,무장/허용을 자동 복구하지 않습니다.
연결 키는 OS보안 저장소에 기존 값이 남아 있을 수 있으므로 별도로 확인해야 합니다.
추천 조건은 복원한 이력에서 확인/복귀할 수 있지만 전체 settings와 익절손절 정책을 자동 복구하는 절차는 아닙니다.
새 기기에서 프로그램 설치·키 재등록·계좌 대조와 실제 운영 복구 검증은 아직 남아 있습니다.
