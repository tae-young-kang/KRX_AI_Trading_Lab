# 테마1 요구사항과 구현 순서

사용자 요청/확인: 2026-10-18 한국 시간. 기존 개발을 대체하지 않고 발굴 방법을 추가합니다.

2026-10-18 사용자 재확인: 이 문서는 가능한 추가 방식의 명세입니다. 제품 전체 개발 계획은
DEVELOPMENT_ROADMAP.md의 원래 단계 0~12를 따릅니다. 테마1은 별도 선택 기능이며
기존 추천 조건·성과 기반 개선·주문 흐름의 기본 동작을 대체하거나 강제하지 않습니다.
아래 후속 주문 방식도 선택 경로로 유지하며 모든 주문의 기본 정책으로 자동 전환하지 않습니다.

## 확정한 발굴 기준

- 코스피·코스닥, 확인된 최근 6거래일의 이동 구간. 주말뿐 아니라 공식 휴장일 제외.
- 하루 조건: 거래대금 100억 원 이상 AND 전일 종가 대비 당일 고가 상승률 5% 이상.
- 6거래일 중 3일 이상 동시에 만족하면 감지. 7일차에는 최초 거래일을 제외.
- 만족한 날이 4일 이상이면 모든 날짜를 표시(사용자 확인).
- 전체 시장 일별 일괄 자료를 재사용하고 거래대금 100억 이상을 먼저 걸러 고가 조건 계산.
- 거래량이 아니라 거래대금이며, 종가 상승률이 아니라 장중 고가의 전일 종가 대비 상승률.
- 첫 평가일의 전일 종가까지 필요하므로 최소 7거래일 자료가 필요. 누락을 조건 미달로 추정하지 않음.
- 일별 확정 자료 판정부터 구현. 장중 미완성 자료는 별도 상태로 취급할 후속 기능.

## 종목별 텔레그램 알림 요구

제목 테마1, 종목명/코드, 감지일/요일, 코스피/코스닥, 감지일 시총,
감지일 기준 NXT 가능 여부 또는 KRX 전용 여부(출처·기준일 확인; 모르면 미확인).
최근 6거래일 범위와 조건 만족한 모든 날짜의 고가 상승률·거래대금 표시.
사용자가 요청한 고가 퍼센트 합계와 65 경계 표시 필요.
사용자 확정: 조건을 만족한 모든 날짜의 고가 상승률 합계로 65%와 비교합니다.
65 정확히 같은 경우는 같음으로 구분. 날짜별 금액과 총액은 다른 항목으로 명확히 표시.
중복 알림 정책·재시작 후 재발송·새 만족일 추가 시 알림·전체 테마 목록 고정은 후속 설계.
테마2/3 등 추가 가능한 분리된 발굴 방법 구조 유지.

## 주문·감시·결산 요구 (현재 미연결)

- 사용자 검토 후 텔레그램으로 종목명 + 주수 또는 금액 요청.
- 금액 주문은 소수점 주수 버림. 시장가의 확정 매수가를 사전에 알 수 없으므로
  수량 산정 기준·수수료/가격 변동 여유·재확인·최대 금액/주수/일일 한도를 구현/검증해야 함.
- 저녁/당일 아침 요청을 다음 허용 세션에 실행하도록 예약 상태 관리.
- 사용자 선택: NXT 가능 종목은 NXT 첫 거래, 나머지는 KRX 시초가.
  시장별 첫 거래·허용 주문 유형·예약 지원을 공식 자료와 어댑터로 검증해야 하며
  시장가 요청이 특정 시초가 체결을 보장하지 않음. NXT 불가를 KRX로 임의 전환하지 않음.
- 기본 익절 +2%, 손절 -3%; 매수 요청별 변경 가능. 체결된 수량/가중 매수가 기준.
- 매수 체결 피드백, 익절·손절 감시/주문, 매도 체결 피드백 및 비용 포함 실현손익.
  익절과 손절의 중복 매도·잔량 초과·부분체결·프로그램 중단·갭하락을 검증해야 함.
  두 주문을 무조건 동시에 보내지 않으며 브로커 지원 여부에 따라 검증된 감시/취소 흐름 필요.
- 종목별 매수금액 합계·매도금액 합계·실현손익과 예수금 부족 안내.
- 테마1 전체 실행 요청: 사용자가 지정한 총예산을 대상 종목에 균등 배분(사용자 확정).
  명확한 대상 목록·예상 주수·종목별 예산·총액 확인 후 실행하며 기본 수량/예산을 추정하지 않습니다.
- 당일 전체 손익 질의 및 익절/손절 종목 수·승률. 미청산/부분매도/본전/수동매도는 구분.
- 매일 20:30 한국 시간 자동 결산 요구. 휴장일/재시작 누락/일일 중복 방지는 후속 설계.
  Codex 자동화가 아니라 제품 내 운영 기능. 현재 실제 발송 스케줄은 생성하지 않음.

## 테마1 저장 자료 연결 첫 단계

app/theme_store.py는 명시적 거래일과 HistoryStore의 지정 출처 일별 캐시를 한 번 읽어 판정합니다.
이는 전체 시장 수집 완료 증명이 아닙니다. coverage=CACHED_SYMBOLS_ONLY로 제한을 명시하고
누락된 종목별 날짜를 PRICE_MISSING으로 집계합니다. 캐시에 전혀 없는 종목은 알 수 없습니다.
감지 근거와 종목별 문안을 theme_alerts에 저장하며 동일 근거는 재시작 후 중복 준비하지 않습니다.
수정된 근거는 별도 버전으로 보존합니다. 상태 PREPARED는 발송 성공이 아니며 자동 송신하지 않습니다.
이 단계의 알림은 NXT 공식 대상 목록 미연결로 미확인을 표시합니다.
실제 송신의 응답 유실·재시작 처리와 중복 발송 방지는 아직 구현/검증 전입니다.

최신 판정 조회는 그 판정에 속한 종목만 보여줍니다. 자료 수정 후 조건에서 빠진 종목을
과거 알림 준비 기록에서 다시 가져오지 않습니다. 시장별 날짜 누락과 종목별 가격 누락을
표시하며, 자료가 있는 시장/날짜라도 전체 종목 수집이 완료됐다고 추정하지 않습니다.
판정이 0종목인 경우도 근거 상태와 함께 저장합니다. 아직 PC/텔레그램 명령 연결 전입니다.

저장 결과 조회: PC 홈 ‘테마1 · 저장된 감지 종목 보기’, 텔레그램 /테마1 또는 /테마1 2.
현재 모드의 최신 판정과 해당 자료 출처를 보여주며 한 종목씩 페이지로 조회합니다.
이 동작은 저장 기록 조회로 새 검색/발송/주문을 실행하지 않습니다. 수신 중지 후에도 읽기는 가능하며
기존 허용 사용자 검사를 거칩니다. 실제 화면 배치와 텔레그램 송수신 검증은 아직 남아 있습니다.
자료를 선택해 테마1 판정을 생성하는 기본 사용자 경로는 후속 작업입니다.

## 저장 자료로 직접 판정하기 (고급)

1. 고급 연구에서 KRX 과거 시세를 수집하거나 확인한 일별 CSV를 불러옵니다.
2. ‘테마1 · 저장 시세와 확인한 거래일로 판정하기 (고급)’를 누릅니다.
3. 아래 구조의 로컬 JSON 선택 파일을 고릅니다. 시세 자체가 아니라 사용할 출처/거래일을 고릅니다.
4. 홈 테마1 저장 결과 또는 텔레그램 /테마1에서 확인합니다. 이 과정에서 발송/주문하지 않습니다.

필드: version=1, mode=현재 모드(DEMO/MOCK/REAL_QUOTES), source=KRX 또는 CSV_USER,
through=확인 완료된 거래일(YYYY-MM-DD), calendar={days:[확인한 거래일 목록],begin:범위 시작,end:범위 끝,source:USER_CONFIRMED}.
최소 7개 거래일이 필요하며 휴장일은 확인한 목록에서 제외합니다. 오늘 이후 기준일은 거부합니다.
사용자 파일은 OFFICIAL 출처를 주장할 수 없습니다. KRX 시세 출처여도 직접 고른 거래일은 USER_CONFIRMED입니다.
DEMO는 source/calendar.source 모두 DEMO만 허용합니다. 기존 연구의 DEMO_SYNTHETIC 캐시와는 별개이며 자동 변환하지 않습니다.
파일 크기는 100KB 이하. 파일 경로나 원본 내용은 판정 기록에 저장하지 않습니다.
이 경로는 수동 고급 입력입니다. 공식 거래일 자동 연결과 쉬운 최초 준비 화면은 후속 작업입니다.

## 총예산 균등 배분 미리보기 기반

app/budget_preview.py는 네트워크 없는 계산부입니다. 선택한 대상 목록과 총예산을 받아
종목당 원 단위 예산을 내리고, 기준 가격에 명시한 수수료/가격 여유(basis points, 1bp=0.01%)를
반영한 1주 예상 확보액을 올림한 뒤 주수를 내립니다. 미사용 금액은 재배분하지 않습니다.
예수금이 아니라 별도 확인한 주문 가용 금액을 입력해야 하며 미확인/부족을 구분합니다.
가용 금액이 예산보다 적으면 계산한 실제 예상액이 작아도 예산 부족으로 표시합니다.
가격 누락/1주 미만을 종목별 표시하며 중복 종목은 거부합니다.
현재는 계산부만 구현됐고 화면/텔레그램/예약/주문에 연결하지 않았습니다. executable은 항상 false입니다.
가격 시각·시장·세션·NXT 대상·확정 체결가·주문 가능 금액의 최신성은 이 함수가 보장하지 않습니다.
실제 주문 단계에서는 신선한 가격/가용금액 대조, 시장가 변동, 총한도·확인·전송 상태를 별도로 검증해야 합니다.

테마1 경계 보강: 입력 소수의 고가 상승률은 분수 계산으로 비교해 중간 나눗셈 반올림이
5%/65% 판정에 영향을 주지 않게 합니다. 합계가 표시 가능한 유한 범위를 넘으면 거부합니다.
고가/거래대금의 같은 날 동시 충족, 중복 날짜, 비정상 OHLC, 기준일 이후 자료 제외를 검사합니다.

## 영속 단일 전송 경계 (미연결)

app/theme_delivery.py는 주입한 송신 함수만 호출하는 기반이며 실제 네트워크 클라이언트는 없습니다.
최신 판정에 속한 알림만 시도하고, 대상별 전송 시도를 먼저 저장한 후 송신합니다.
양의 정수 메시지 번호 응답을 받아야 SENT, 예외/응답 미확인은 UNKNOWN입니다.
중단 시 남은 SENDING도 조회/재호출에는 UNKNOWN으로 취급하며 자동 재시도하지 않습니다.
성공·미확인 모두 같은 대상의 같은 알림은 다시 전송하지 않습니다. 이는 정확히 한 번 도착 보장이
아니며 중단 시 미발송 알림이 남을 수 있습니다. 별도 사용자 대조/수동 재발송 흐름은 후속입니다.
송신 대상은 원문 방 번호/키 대신 SHA-256 범위 식별자를 받습니다. 실제 연결부는 승인한 대상과
이 식별자를 고정 결합해야 합니다. 현재 제품 화면/수신 worker에 연결하지 않았습니다.
알림 길이는 4,000자 이하만 허용합니다. 모드/자료 출처와 최신 판정 목록을 확인합니다.

전송 응답 확인: TelegramTransport.send는 양의 메시지 번호와 요청 대화방 일치를 확인하고
메시지 번호를 반환합니다. 잘못된 응답은 자동 재시도하지 않습니다.
대상 범위는 봇/개인 대화방 조합의 해시로 구분하며 원문 번호는 전송 장부에 넣지 않습니다.
최신 판정의 발송 응답 확인·미확인·미시도 집계 함수가 추가됐습니다. 아직 상태 화면/명령 연결 전입니다.

텔레그램 /테마1알림상태 로 수신 시작 당시 모드의 최신 판정에 대한 발송 응답 확인·결과 미확인·미시도
개수를 확인합니다. 허용된 봇/개인 대화방 범위를 사용하고 다른 대상의 기록을 섞지 않습니다.
수신 중지 후에도 기록 조회는 가능하며 실제 송신이나 재시도를 실행하지 않습니다.
실제 알림 전송 사용자 경로는 아직 미연결이므로 기존 준비 기록은 미시도로 표시됩니다.

## 명시적 PC 알림 송신 연결

테마1 저장 결과 창의 ‘저장된 최신 테마1 종목을 텔레그램으로 보내기’를 누르면
기준일·출처·종목 수를 확인한 후 저장된 개인방으로 전송합니다. 실제 주문은 하지 않습니다.
확인 시점의 판정 번호를 고정하고 판정 변경 시 차단합니다. 봇 식별 응답과 개인방으로 대상 해시를 구성합니다.
이미 시도한 알림은 재송신하지 않으며 미확인에서 일괄 송신을 중단합니다. 남은 수를 표시합니다.
‘발송 응답 확인’ 집계는 기존 성공도 포함합니다. 읽음이나 정확히 한 번 도착 보장이 아닙니다.
실제 발송 버튼 경로가 추가됐지만 개발 검증은 가짜 송신기만 사용했습니다. 실제 GUI/송수신 검증은 남습니다.
자동 감지/자동 발송·NXT 공식 대상 목록과 공식 거래일 자동 연결은 여전히 후속입니다.

일괄 전송 중 미확인에서 중단된 경우 ‘미시도 알림만 이어 보내기’를 선택할 수 있습니다.
확인창에서 기존 미확인은 건너뛰며 아직 시도하지 않은 종목만 보낸다고 안내합니다.
기존 성공/미확인은 재전송하지 않고 새 미확인이 생기면 다시 중단합니다.
결과 미확인을 성공으로 바꾸거나 재발송하는 기능은 아닙니다. 원래 확인/기본 전송 방식도 유지합니다.
전송부는 종목 사이 중지 콜백을 지원하지만 현재 GUI 작업 취소 버튼과는 연결하지 않았습니다.

## 테마1 예산 미리보기 화면

테마1 저장 결과 창에서 ‘총예산으로 예상 주수 보기 · 주문 안 함’을 누릅니다.
총예산→수수료 가정→가격 여유를 입력하면 감지된 전체 종목에 균등 배분한 예상 주수를 보여줍니다.
계산 가격은 판정 당시 함께 저장한 기준일 종가입니다. 현재가/예정 시초가가 아니며 이후 캐시 수정을
끼워 넣지 않습니다. 이전 기록에 기준 종가가 없으면 미확인으로 남깁니다. 새 판정부터 종가를 저장합니다.
계좌의 주문 가능 금액을 조회하지 않으며 실제 매수 가능 여부는 미확인, 주문/예수금 예약 없음으로 표시합니다.
원 단위 정수가 아닌 가격은 이 주수 계산에서는 미확인입니다. 실제 주문 지원을 의미하지 않습니다.
실제 화면 조작 검증은 미완료이며 텔레그램 예산 미리보기 명령은 후속입니다.

텔레그램 예산 미리보기: /테마1예산 총예산 수수료% 가격여유% [페이지].
예: /테마1예산 1000000 0.02 2 는 100만원을 수수료 가정 0.02%, 여유 2%로 계산합니다.
종목 5개씩 보여주며 전체 예산/확보액/미사용 금액 합계는 전체 대상 기준입니다.
이 명령은 저장된 최신 판정/종가를 조회해 계산만 하며 주문·예약·가용금액 조회를 하지 않습니다.
페이지별 판정 번호를 확인하세요. 사이에 새 판정이 생성되면 최신 판정으로 바뀔 수 있습니다.
실제 송수신 검증은 아직 남아 있습니다.

테마1도 자료→판정→알림→선택 주문/감시→결산과 실제 검증까지 별도로 완료를 추적합니다.
원래 계획 유지와 테마1 완성을 모두 요구한 사용자의 재확인 사항입니다.

테마1 자료 선택·판정 기준일과 거래일 목록도 공통 YYYY-MM-DD 검증을 사용합니다.
압축/주차/공백 날짜가 다른 저장 키로 섞이지 않게 입력에서 거부합니다.

테마1과 원래 연구 기능이 공유하는 KRX 일별 캐시는 당일/빈 응답을 확정 자료로 고정하지 않습니다.
다음 날짜 재관측과 행 수를 확인해 캐시를 재사용하며 전체 시장 완료 증명은 별도 미완료입니다.

## 판정 당시 수집 상태 고정

테마1은 가격과 수집 관측을 같은 SQLite 읽기 시점에서 읽습니다. 판정/종목 알림에는 전일 종가를
포함한 7거래일의 원본 수 미확인 일수·정규화 제외 행 수·관측/가격 행 수 불일치 일수를 함께 보존합니다.
나중에 관측 상태가 바뀌어도 과거 결과를 바꾸지 않고 새 판정으로 별도 버전을 만듭니다.
빈 응답 후 기존 가격 보존처럼 관측과 캐시 행 수가 다르면 불일치로 안내합니다.
이 메타데이터는 저장 자료 범위의 품질 안내이며 전체 상장 종목 수집 완료/공식 확정 증명이 아닙니다.

## 날짜별 NXT 관측 보존과 테마1 연결

전체 종목 검색이 완료되면 NXT 관측을 모드/시장/종목/시각별로 research.db에 보존합니다.
DEMO에 키움 관측을 섞지 않으며 같은 시각의 상충된 값은 자동 덮어쓰기하지 않습니다.
테마1은 가격·수집 관측·동일 감지일의 NXT 관측을 같은 읽기 시점에서 가져오고 가장 최근 관측을 고정합니다.
다른 날짜/모드의 긍정값은 쓰지 않습니다. 이후 미확인 관측은 이전 긍정보다 우선하며 새 판정에 반영합니다.
이미 만든 알림은 바꾸지 않습니다. 관측 시각과 현재 주문 가능 상태 보장이 아니라는 안내도 표시합니다.
NXT 저장 실패는 PC에서 안내하고 추천/가상 계산과 별도로 취급합니다. 과거 저장 관측 자체를 지우지는 않습니다.
이 값은 조회 당시의 명시적 긍정/미확인이며 NXT 불가/다음 세션의 실행 가능 여부는 미확인입니다.
NXT 주문·시장 자동 선택·실계좌 주문을 활성화하지 않습니다. 실제 API 관측/운영 검증은 남아 있습니다.

테마1은 저장된 NXT 근거를 읽을 때도 모드·한국 날짜·시간대 포함 시각·코드·긍정/미확인을 검증합니다.
잘못된 근거가 있으면 새 판정을 생성하지 않고 확인을 안내합니다. 최신 관측은 문자 정렬 대신 실제 시각으로 선택합니다.

## 테마1 예산과 매수 후 계획 미리보기

기본 익절 +2%·손절 -3%를 함께 표시합니다. 검토용 비율을 바꾸려면
/테마1예산 1000000 0.02 2 익절 4.25 손절 1.75 처럼 입력합니다.
페이지는 기존처럼 가격 여유 다음에 넣습니다. 다음 페이지 명령에도 선택 비율을 유지합니다.
비율은 0.01% 이상 100% 미만이며 해당 미리보기에만 적용합니다. 저장 설정 변경이나 주문 확인이 아닙니다.
저장 종가는 예상 주수 계산용이고 매도 목표가는 실제 체결가 확인 전 계산하지 않습니다.
매도 감시·예약·시장 자동 선택은 아직 연결되지 않았습니다. NXT/다음 첫 거래 가능 여부도 실행 전 재확인이 필요합니다.

## 체결 기반 보호 판단 계산부

app/protection_plan.py는 대조 완료로 전달된 누적 매수 체결 수량/금액과 이미 판 수량으로
남은 수량을 계산하고 체결 평균가 대비 익절/손절 경계를 정수 연산으로 판단합니다.
부분체결의 소수 평균가를 반올림하지 않습니다. 매수 접수 수량을 체결 수량으로 취급하지 않습니다.
매도 대기 수량이 있으면 새 판단을 보류합니다. 같은 모드/종목/시장과 시간대 포함 시세/수신 시각을
요구하고 30초 초과·미래·순서 불일치 시세는 차단합니다. 기본 +2%/-3%, 사용자 지정 비율 검증 공통화.
이 계산부는 입력 근거를 증권사와 직접 검증하거나 새 시세를 받지 않습니다. caller의 대조 완료 표시는
외부 체결 증명이 아닙니다. 모든 결과 executable=False이며 주문·영속 감시·예약과 아직 연결되지 않았습니다.
가격 조건은 비용 전 체결 평균가 기준입니다. 조건 도달 가격에 실제 매도된다는 보장이나 순수익 계산이 아닙니다.
후속: 영속 체결/잔량/매도 주문 상태와 결합, 최신 시세·실제 운영 검증, 결과 알림·결산.

## 모의 체결 장부와 보호 계산 연결

app/mock_protection.py는 같은 모의 계좌의 당일 30초 이내 조회 묶음과 영속 장부의 최신
snapshot이 정확히 같은지 확인합니다. 사용자가 아닌 호출부가 명시한 매수/매도 주문번호별
체결을 모아 평균가/매도 수량을 계산하고 보유·매도 가능 수량과 대조합니다.
연결되지 않은 같은 종목 체결, 겹친 주문번호, 누락 주문, 같은 종목 미체결은 차단합니다.
미체결 조회의 방향 근거가 부족하므로 미체결 매수도 안전하다고 추정하지 않습니다.

reconciled는 이 내부 대조가 통과했다는 뜻이며 HTS/MTS 독립 대조/실제 체결 검증이나
주문 실행 허용은 아닙니다. 계산 결과는 계속 executable=False이고 장부/주문을 변경하지 않습니다.

## 보호 관측 상태의 영속 저장

app/protection_watch.py는 별도 모드/계좌 파일에 종목·시장·익절손절 정책과 관측 판단을 저장합니다.
계획 키 재등록은 동일 내용만 허용하며 같은 종목의 별도 중복 계획도 차단합니다.
관측 시각 역행을 차단하고, 동일 입력/판단은 중복 기록하지 않습니다. 최초 익절/손절 도달은
TRIGGERED로 고정해 동시 호출이나 재시작 후 new_trigger가 다시 참이 되지 않습니다.
TRIGGERED 반환값은 최초 저장 판단이며 현재의 매도 수량/시세를 재보증하지 않습니다.
미대조/오래된 시세의 BLOCKED 결과는 감지 완료로 승격하지 않습니다.
observe_mock은 앞서 만든 최신 모의 장부/조회 대조를 거쳐 계산합니다. 직접 observe는 내부 계산 API이며
독립 계좌 검증을 대신하지 않습니다. 모든 결과 executable=False, 주문 전송·자동 감시 루프·재개/재무장은 미연결입니다.
현재 같은 종목 재등록/다음 투자 주기 시작 절차는 후속이며 사용 중인 계획을 임의 덮어쓰지 않습니다.

/보호상태 [페이지] 는 마지막 연결된 키움 모의 보호 관측 기록을 5개씩 읽습니다.
조건·마지막 관측 시각·판단 이유·당시 수량을 표시하며 내부 계좌 구분값이나 파일 경로는 보내지 않습니다.
조건 도달은 최초 판단 기록으로 고정된 값이고 현재 보유/매도 가능량이나 실제 매도 접수/체결을 뜻하지 않습니다.
계획 등록/관측 자체의 기본 사용자 경로·자동 감시/주문 실행은 아직 미연결입니다.
수신의 새 요청을 중지한 후에도 조회할 수 있으며 연결 전에는 기록 연결 전을 안내합니다.

## 전체 매수 계획을 여러 페이지로 검토할 때

`/테마1계획 전체 100만원` 또는 `/테마1예산 1000000 0.02 2`의 답장에 있는 다음 명령을 그대로 사용하세요.
다음 명령에는 `판정 번호`가 포함돼 검색이 새로 끝나도 처음 보던 감지 목록과 저장 종가를 유지합니다.
예산·수수료 가정·가격 여유·익절/손절도 다음 페이지에 유지합니다.
판정 번호를 생략하고 처음부터 요청하면 현재 모드의 최신 판정으로 새 계획을 봅니다.
