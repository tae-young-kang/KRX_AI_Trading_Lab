# 과거 시세 누락 대조 (읽기 전용)

## 왜 필요한가?

기존 연구 엔진은 저장된 종목 일봉의 날짜 합집합을 시장 거래일로 참고합니다.
KRX 또는 CSV 원본에서 어떤 거래일의 시장 전체 자료가 통째로 빠지면,
이 기록만으로는 그 날짜가 누락되었는지 알 수 없습니다.

연구 화면에서 **저장 일봉과 외부 거래일·최소 종목 수 대조 (고급)**을 누른 뒤
**별도 출처에서 확인한** 거래일·최소 종목 수 CSV를 선택하면 현재 연구 데이터
(`CSV_USER`, `KRX`, `DEMO_SYNTHETIC`)와 읽기 전용으로 비교합니다.

CSV 파일의 헤더와 각 열은 반드시 아래와 같아야 합니다.

```csv
market,day,min_symbols
KOSPI,2026-10-13,3
KOSDAQ,2026-10-13,2
KOSPI,2026-10-14,3
```

**위 숫자와 날짜는 작동 방식 설명용 가상 예시입니다. 실제 KRX 최소 상장 종목 수나
공식 거래일을 뜻하지 않습니다.** 실제 비교에는 공개·별도 검증된
과거 거래일 자료 및 신뢰할 수 있는 최소 종목 수를 사용하세요.
같은 로컬 시세 DB에서 만든 목록은 독립 검증이 아닙니다.

- `market`: `KOSPI` 또는 `KOSDAQ`
- `day`: 정확한 `YYYY-MM-DD`. 명시된 거래일만 검사하며 공휴일을 추측하지 않습니다.
- `min_symbols`: 그 날짜의 **최소한으로 존재해야 할 종목 수**를 뜻하는 양의 정수입니다.
  실제 상장된 전체 종목 수와 반드시 같을 필요는 없지만 너무 낮으면 누락 감지력이 떨어집니다.
- 동일 시장·날짜를 중복 입력할 수 없고, 다른 열/잘못된 날짜/과도한 파일 크기는 거부됩니다.
  최대 10,000개의 시장·날짜 행, 1 MB를 허용합니다.

## 결과 해석

| 표시 | 의미 |
| --- | --- |
| 저장 자료 없는 날 | 외부 입력의 특정 시장·거래일에 저장된 일봉이 하나도 없음 |
| 최소 종목 수 미달 | 저장된 종목 수가 입력 하한보다 적음 |
| 종목 수 급감 의심 | *직전 입력 거래일*의 저장 종목 수보다 30%를 초과해 감소 |
| 정규화 제외 관측 | 수신 집계가 남아 있고, 유효 가격/종목으로 변환하지 못한 행이 있음 |
| 최소 하한 충족 | 입력 하한 이상이지만, **모든 상장 종목 수집 완료를 증명하지 않음** |

경고들은 한 날짜에 여러 개 발생할 수 있으며 실제 수정·재수집을 자동 실행하지 않습니다.
저장 파일/설정/계좌 기록도 변경하지 않습니다. 한 날짜의 종목 수가 줄었다고 반드시
데이터 오류인 것은 아닙니다. 종목 정지·상장/폐지·ETF 포함 여부·가격 유효성 차이
때문일 수 있으므로 원본과 대조해야 합니다.

## 명확한 제한

이 기능은 입력 CSV가 공식적으로 참인지 인증하지 않습니다.
거래 정지 종목의 집계, KRX 전체 상장 종목 구성, 분할/배당/수정주가, 개별 종목
누락, 당시 호가/체결 가능성도 검증하지 않습니다. `KRX` 저장 데이터라도 이전에
종가 확정 확인이 된 일봉인지 자동 인정하지 않으며,
**이 결과만으로 투자전략을 승인하거나 주문을 실행하지 않습니다.**

실제 PC GUI 조작, 사용자 개인 데이터, 시장/KRX 접속 및 키움 모의·실계좌 주문 테스트는
이 브랜치의 자동화 테스트에 포함하지 않습니다.

## 구현 후 입력 검사 보강

급감의 비교 대상은 실제로 연속된 거래일이라고 추정한 날짜가 아니라 **외부 CSV에 바로 전에
나온 해당 시장의 이전 입력 거래일**입니다. 따라서 입력 CSV가 건너뛴 날이 있다면 급감
해석에 영향을 줄 수 있습니다. 이 기능은 가격/거래량 누락을 자동 보정하지 않습니다.
