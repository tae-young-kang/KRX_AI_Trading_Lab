# 개발과 독립 검증 기록

적용 범위는 원래 로드맵0~12/A~F, 테마1, 이후 승인된 모든 목표입니다.
전체 기능 연결을 우선하며 한 영역의 예외 보강 때문에 다른 목표를 계속 미루지 않습니다.

## 역할과 순서

| 역할 | 책임 | 하지 않는 일 |
|---|---|---|
| 개발 담당 | 완료 기준에 맞게 구현하고 자체 검사·변경 설명 제공, 지적 사항 수정 | 자기 변경의 최종 완료 판정 |
| 검증 담당 | 고정된 변경을 독립 검토·검사하고 요구 충족 여부와 남은 작업 보고 | 제품 코드 직접 수정, 오프라인 결과를 실제 실행으로 표시 |
| 조정자 | 범위·완료 기준 확정, 검증 결과로 수락/반환, 최종 diff·정확한 staged 비밀정보 검사, 커밋·푸시·원격 확인·인수인계 | 독립 검증 생략, 실패·미구현을 완료로 표시 |

1. 조정자가 소목표와 관찰 가능한 완료 기준을 기록합니다.
2. 개발 담당이 구현·자체 검사를 마치고 변경 범위를 고정합니다.
3. 별도 검증 담당이 해당 HEAD·diff를 확인하고 관련 검사를 독립 수행합니다.
4. 문제는 개발 담당이 수정하고, 변경으로 영향을 받은 범위를 재검증합니다.
5. 조정자가 수락한 범위만 저장·커밋·푸시하고 다음 연결 작업으로 이어갑니다.

같은 파일을 개발·검증 담당이 동시에 수정하지 않습니다. 독립 검증 담당이 없으면 검증 대기로 남깁니다.
모든 담당은 GUI/main.py·실제 시장/계좌/Telegram 실행을 하지 않는 현재 범위와 실계좌 주문 금지,
비밀정보 업로드 금지를 지킵니다. 실제 환경 검증은 필요한 별도 허용 범위에서만 수행합니다.

## 전체 목표 대응 기록

전체 목표의 기준은 DEVELOPMENT_ROADMAP.md 원본입니다. 이 문서에 별도 목표를 만들거나
기존 단계0~12, A~F, 테마1 요구사항을 서로 대체하지 않습니다. 아래 대응표를 이 문서에서
유지하고, 소목표 검증 기록의 위치를 연결해 전체 목표의 달성 근거를 한 곳에서 찾도록 합니다.
한 변경이 여러 요구에 해당하면 각각 연결하고, 큰 요구의 일부만 충족했으면 부분으로 기록합니다.
독립 검증 기록이 없는 기존 구현은 자동 통과시키지 않고 상태 미확인으로 남깁니다.
이번 문서 작업은 과거 구현 전체 재감사나 완성률 산출을 수행한 것이 아닙니다.

| 요구사항 ID | 로드맵 원본 위치 / 범위 | 관련 소목표·검증 기록 링크 | 구현 / 오프라인 독립 검증 / 실환경 상태 | 남은 확인 |
|---|---|---|---|---|
| 단계0~12 / A~F / 테마1의 개별 요구 ID를 기록 | 원본 제목과 해당 요구 | WORK_CONTINUATION.md 등 실제 검증 기록 링크 | 미검증이면 상태 미확인 | 다음 확인을 기록 |

위 행은 작성 양식입니다. 개별 요구를 대조할 때 실제 행으로 추가하며, 빈 양식이나 과거
테스트 수를 전체 목표의 달성 근거로 사용하지 않습니다.

## 소목표 기록 양식

아래 내용을 WORK_CONTINUATION.md 또는 해당 작업의 인수인계 기록에 남깁니다.
이 문서는 양식이며, 작성만으로 검증이나 목표가 완료된 것은 아닙니다.

```text
소목표 / 날짜:
요구사항 ID: 로드맵 단계 / A~F / 테마1 요구사항
개발 담당 / 독립 검증 담당 / 조정자:
범위 / 제외 범위:
완료 기준: 사용자가 관찰할 동작과 실패 시 동작
변경 파일:
검증 대상: 기준 HEAD SHA + 변경 파일 목록 + diff 식별 정보
  - 이미 커밋된 변경이면 대상 커밋 SHA와 비교 기준 SHA
  - 미커밋 변경이면 기준 HEAD SHA와 고정 diff의 해시·생성 방법
  - 검토 뒤 변경되면 영향 범위를 적고 재검증
개발 자체 검사: 명령 / 결과 / 사용하는 임시·가짜 자료
독립 검사: 명령 / 결과 / 확인한 코드·동작 근거
완료 기준별 판정:
  - 기준 / 충족·부분·미충족·실환경 미확인 / 근거 / 남은 확인
구현 상태:
오프라인 독립 검증 상태:
실제 환경 검증 상태: 미실행 / 별도 확인 결과와 근거
차단 사항 / 지적 사항 / 수정·재검증 결과:
남은 요구사항 / 다음 작업:
조정자 수락 또는 반환 사유:
정확한 staged 비밀정보 검사 결과:
커밋 SHA / Push 결과 / 원격 SHA 대조:
인수인계 저장 위치:
```

판정은 완료 기준별로 붙입니다. 일부 기준 충족을 전체 목표 완료로 확대하지 않습니다.
실제 환경에서만 확인할 수 있는 사항은 실환경 미확인으로 남기고, 오프라인 검증을 통과한
구현 범위를 별도로 기록할 수 있습니다. 테스트 개수나 기록 양을 전체 완성률로 계산하지 않습니다.
