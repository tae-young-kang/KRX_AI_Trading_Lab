# 48개 조건 비교 — 학습·검증 격차와 자료 품질

## 목적

매수·매도 타이밍의 최적화보다 **수익 가능성이 높은 종목을 찾는 스크리닝 조건의 검증**에 집중합니다.
48개 후보 조건이 학습 기간에 높은 성과를 보였더라도 검증 기간까지 유지되는지, 실제로는
종목 수가 부족하거나 데이터 자체가 검증되지 않았는지를 함께 살펴봅니다.

새로운 **학습→검증 차이(%p)** 는 다음처럼 계산합니다.

```text
학습→검증 초과수익 차이 = 검증 기간의 3거래일 평균 초과수익률
                         - 학습 기간의 3거래일 평균 초과수익률
```

예시: 학습 초과수익 +2.0%p, 검증 초과수익 -0.5%p이면 차이는 -2.5%p입니다.
기존 평균 초과수익과 같이 **날짜별 동일 가중의 기술통계**이며,
누적 투자수익률·실제 계좌 수익·손절/익절 체결을 뜻하지 않습니다.

## 사용자 화면과 CSV

연구 화면의 48개 조건 비교 표에 `학습→검증 차이(%p)`, `자료/결과 해석`을 추가했습니다.
조건별 결과 내보내기 `summary.csv`에는 다음 5개 필드를 덧붙입니다.

| 열 | 의미 |
| --- | --- |
| `holdout_gap3` | 3거래일 학습 초과수익과 검증 초과수익의 차이(%p) |
| `data_quality_label` | 연구 전체 자료의 독립 대조 상태 |
| `comparison_note` | 표본 부족, 학습 대비 검증 수익 감소 등 조건별 경고 |
| `adequate_train_days` | 학습 12개 평가 거래일 이상 여부 |
| `adequate_test_days` | 검증 5개 평가 거래일 이상 여부 |

표본 수 12/5는 화면 경고를 위한 초기 안내 기준이며 통계적 유의성 기준이 아닙니다.
마지막 TEST 구간의 결과가 좋아도 새로운 조건을 선정·자동 적용하지 않습니다.
학습 구간 성과로만 기존 순위를 정하며 48개 조건 모두 같은 기간/시장을 공유해
결과가 서로 독립적이지 않을 수 있습니다. 여러 조건을 비교한 뒤 검증 구간 성과가 가장
좋은 조건을 다시 선택하면 검증 구간에 맞춰 과적합할 수 있습니다.

## 품질 상태와 한계

- `ALERT`: 외부 참조에서 누락/의심 자료가 있어 성과를 신뢰하기 어려움
- `NOT_CHECKED`: 독립 시장 거래일·종목 수 대조를 하지 않은 자료
- `REFERENCE_FLOOR_MET`: **사용자가 입력한 최소 종목 수 기준만** 충족한 자료

품질은 **조건별 인증 지표가 아니라 이번 연구 입력 전체의 출처/범위에 대한 상태**입니다.
개별 종목의 수정주가·기업행동, 상장폐지 종목 누락, 거래 가능 시가,
매수·매도 비용, 동시 포지션 및 보유 기간의 중첩을 검증하지 않습니다.
특히 표시된 초과수익 격차가 줄었다고 해서 미래 수익 가능성이 입증되는 것은 아닙니다.

기존 연구 결과 파일에 독립 대조 기록이 없을 때에는 `외부 대조 기록 없음`으로 표시합니다.
검증 기간의 값이 없거나 숫자가 비정상이면 차이를 임의로 0에 맞추지 않고 비워 둡니다.
비교표와 CSV는 원래의 학습 구간 정렬 순서를 변경하지 않습니다.

## 검증 방식

GitHub Actions Python 3.11에서 전체 오프라인 회귀 테스트(단, `tests/test_scan_ui.py` 제외)를 실행합니다.
실제 Windows GUI의 표시 및 사용자가 제출한 시장 데이터의 출처·완전성, 키움 모의 체결 및 실계좌
주문 여부는 별개로 검증해야 합니다. 이 기능은 매매를 실행하지 않습니다.
