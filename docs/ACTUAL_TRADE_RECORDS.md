# 실제 체결 입력과 가상 추적 구분

실제로 산 종목은 체결 근거로, 사지 않은 추천 종목은 가상 추적으로 기록합니다.
키움 모의계좌 기록도 별도입니다. 실제 체결이 들어왔다고 가상 기록을 실제 기록으로 바꾸지 않습니다.
현재 추가된 실제 경로는 **사용자 제공 CSV 입력→별도 로컬 기록→텔레그램 하루 조회**입니다.
증권사 자동 수집/대조, 추천 목록과 자동 연결, 매일 아침 NXT/KRX 가상 진입,
20:30 통합 보고까지 구현됐다는 뜻은 아닙니다. 실계좌 주문 기능도 켜지 않습니다.

## 실제 체결 입력

증권사에서 확인한 체결 내역을 아래 CSV 형식으로 준비합니다. 계좌번호·키·토큰은 넣지 않습니다.
CSV는 이 프로그램용 정규화 형식이며 모든 증권사 원본 CSV를 자동 해석하지 않습니다.

```csv
fill_id,filled_at,code,name,venue,side,quantity,price_won,realized_pnl_won,reason
example-buy,2026-10-19T09:00:00+09:00,900001,입력 예제,KRX,BUY,10,1000,,UNKNOWN
example-sale,2026-10-19T09:05:00+09:00,900001,입력 예제,KRX,SELL,10,1100,900,TAKE_PROFIT
```

위 내용은 완전히 가상의 형식 예입니다. 체결 번호는 날짜/주문/체결을 합치는 등 다른 날짜와도
겹치지 않게 만듭니다. 같은 번호/내용은 다시 더하지 않고, 같은 번호의 다른 내용은 전체 입력을 거절합니다.
시간은 시간대를 포함하며 미래 체결은 받지 않습니다. 시장은 `KRX`, `NXT`, `UNKNOWN`입니다.
실제로 체결된 시장을 쓰고 NXT 가능 여부만 보고 체결 시장을 추정하지 않습니다.
`BUY`/`SELL`, 정수 주수와 원화 체결가를 입력합니다. 사유는
`TAKE_PROFIT`/`STOP_LOSS`/`OTHER`/`UNKNOWN`입니다.

`realized_pnl_won`은 **매도 체결에 대해 확인한 실현손익**만 입력합니다. 매수는 비워 둡니다.
분할 체결마다 같은 주문 전체 손익을 중복 입력하지 않습니다. 체결별 손익을 확인할 수 없으면 비워 둡니다.
이월 보유 원가나 세금을 프로그램이 추측해서 손익을 채우지 않습니다.

프로젝트 폴더에서 실행:

```powershell
py -m app.actual_trade_records "C:\내폴더\체결입력.csv"
```

입력은 로컬만 사용하며 API/주문/메시지 발송을 하지 않습니다.
`%LOCALAPPDATA%\KOSPI_AI_Trading\actual_fill_records.db`에 별도 보관합니다.
이 DB와 CSV는 개인 자료이므로 저장소에 올리지 않습니다.

## 텔레그램에서 확인

업데이트가 반영된 프로그램과 허용된 개인 수신 세션에서 `/실제결산` 또는
`/실제결산 2026-10-19`로 조회합니다. 여러 종목은 `날짜 페이지`로 넘깁니다.
읽기 전용이며 해당 날짜의 전체 금액은 페이지마다 동일합니다.

매수/매도 금액은 체결가×수량의 비용 차감 전 금액입니다. 실현손익은 입력한 값만 더합니다.
손익이 빠진 매도가 하나라도 있으면 전체 합계는 미확인, 해당 종목은 승률에서 제외합니다.
승패는 당일 매도한 **종목별 입력 손익** 기준이며 전량 청산된 거래 수가 아닙니다.
익절/손절 사유는 매도 체결 건수로 따로 셉니다. 실제 원본 대조 전 상태를 표시합니다.
입력 기록이 없는 날을 0원 성과로 해석하지 않습니다.
